npm workspaces: libraries in `packages/`, executables and apps in `apps/`.

| Package | Role |
|---|---|
| `packages/protocol` | wire types: canonical JSON, Ed25519 identity, capabilities, intents, grants, rule keys. Pure, no I/O — most invariants live here |
| `packages/transport` | the `Connection`/`ConnectionDialer` seam and the WebSocket **client** half. This Mac only ever dials out, so there is no listener |
| `packages/device-core` | the decision and execution path: policy engine, sandboxed executor, file ops, `hostGate/`, `browser/`, audit log, skill registry, identity store |
| `packages/mcp-server` | the MCP server this Mac serves. **Binds no port** — it takes a `Request` and returns a `Response`, because the relay tunnels a whole HTTP exchange over the device WebSocket |
| `packages/relay-client` | dials the Plow relay and serves the exchanges it tunnels. `wire.ts` is the cross-repo interface |
| `packages/browser-server` | the Camoufox server, a TypeScript port of the retired Python one, driving `playwright-core` on an exact JSON-lines stdio wire |
| `packages/native-keychain` | one N-API addon: the vault master key in the data-protection Keychain |
| `apps/desktop` | the Electron app. The main process runs `device-core`; the renderer is sandboxed |

## The rebuild: a Mac dials out

The in-repo broker — its rendezvous service, the MCP subset, the stdio shim, the
pairing flow — **has been removed**. A Mac now dials *out* to the Plow relay,
which authenticates the calling agent and forwards MCP to the MCP server in the
app. Agent identity is asserted by the relay rather than by an agent-held key
pinned at grant time.

**The relay lives in the private `plow-pbc/plow` repository**, in
`api/plow/relay/`. Latch owns the client that dials it and the server it
forwards to — not the relay. The app *is* the device: no listener, no bound
port, unreachable inbound.

The relay client holds one WebSocket, heartbeats at 15s or under, and reconnects
with full-jitter exponential backoff doubling to a 30s ceiling. The receive loop
never awaits a request, because serving can take the whole call budget and
would stall the heartbeat into staleness.

## The coverage line, said honestly

The policy engine, the capability-derived sandbox, file operations, the audit
log, the approval UI and the reviewer are not just tested — they are the live
path a real caller drives. **The relay leg is verified by hand**, and
`REVIEW.md` records that as an accepted deferral rather than a finding.

What is left automated: the pure wire contract, and the socket lifecycle
(handshake, heartbeat, silent-drop detection, backoff, reconnect) against
hand-written fakes. Nothing in the suite opens a socket or tunnels a call
end to end. The one exception is `scripts/latch-smoke`, which drives a single
real MCP call against an installed app and reads the verdict out of
`audit.ndjson` — **the audit log is the proof, not the client's reply**, because
a reply can come from a deferred handle while an `exec_end` carrying the
intent id cannot.

The `fixtures/` golden vectors were generated by the original Swift
implementation and are now frozen as the protocol spec. Any change to canonical
encoding, signing bytes, rule keys or SBPL that moves those bytes is a declared
protocol break.

## The trap: which DESIGN.md sections are current

`DESIGN.md` was not fully rewritten when the broker went away. Only §3 carries
an explicit **Superseded** banner and §8 an explicit **Historical** one.

Sections that still describe the broker as current, and must not be cited for
present behaviour: **§1** (a `DomoBrokerCore` principal), **§2** (enrollment,
`request_device_access`, minting agent identity at the broker), **§10** (E2E
booting a real `domo-broker` process), **§11** (the Swift target table with
`domo-broker` and `domo-mcp`) and **§13.3** (the target shape listing
`@domo/broker-core`, `apps/broker`, `apps/mcp`).

§3 and §6 are current, and they are the sections that matter for the sandbox and
the tool surface. It is also internally inconsistent on some numbers — a +120s
intent expiry in the §4 example against a 15-minute wait in the code, for
instance — so **prefer the shipped tool descriptions** in
`packages/mcp-server/src/tools.ts` for anything a customer will act on.
